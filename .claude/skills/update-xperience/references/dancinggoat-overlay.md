# DancingGoat overlay

What this repository changes in the generated `kentico-xperience-sample-mvc` project. Use it to resolve merge conflicts: in every conflict, keep the template's new code and re-apply the overlay item that touches the same lines. Code the repository added to demonstrate its own library (widgets, pages, registrations) is overlay too; keep it.

| File | Overlay |
| --- | --- |
| `DancingGoat.csproj` | `ProjectReference` to `Kentico.Xperience.Labs.SimpleStats.Admin` (unconditional, `SeparatedAdmin` ignored); repository's own `UserSecretsId` |
| `Program.cs` | `.AddControllersWithViews(options => options.SuppressImplicitRequiredAttributeForNonNullableReferenceTypes = true)` (needed by `<Nullable>annotations</Nullable>` in `examples/Directory.Build.props`); `builder.Services.AddUtmTracking();` after the `IEmailActivityTrackingEvaluator` registration; `builder.AddDancingGoatLocalEnvironment();` before `AddDancingGoatManagementApi()` |
| `LocalEnvironmentConfiguration.cs` | repository-only: `AddXperienceSmtp()` (fallback for system emails, notifications, and all email channels); binds `SmtpOptions`, `SystemEmailOptions`, `EmailQueueOptions`, and the `AdminIdentityOptions:ExpireTimeSpanMinutes` override from configuration |
| `Samples/UtmTracking/*` | repository-only: stores UTM parameters on landing page activities, so the campaign source reports have data; registered by `AddUtmTracking()` |
| `Components/ViewComponents/TrackingConsent/*`, `Controllers/ConsentController.cs`, `wwwroot/Scripts/trackingConsent.js` | consent banner agrees in the background (`X-Consent-Agree` header) and keeps the query string in `ReturnPageUrl`, so UTM values survive consent |
| `Views/Shared/_DancingGoatLayout.cshtml`, `Views/Shared/_LandingPageLayout.cshtml` | `<script src="~/Scripts/trackingConsent.js" defer></script>` |
| `appsettings.json` | `CMSConnectionString` to `localhost,1433`, database `xperience-by-kentico-simple-stats`, `sa` / `Pass@12345`; `CMSHashStringSalt` is left as `dbmanager` writes it |
| `appsettings.Development.json` | repository's ManagementApi port and secret; `SmtpOptions` (localhost:1025); `SystemEmailOptions`; `EmailQueueOptions`, `CMSProcessContactActionsInterval`, `AdminIdentityOptions:ExpireTimeSpanMinutes`; `CMSAdminClientModuleSettings` Proxy entry for `kentico-xperience-labs-simple-stats-admin` |
| `appsettings.CI.json` | repository-only file for the CI e2e job (`ASPNETCORE_ENVIRONMENT=CI`): SMTP to Mailpit, no admin client Proxy entry |
| `Properties/launchSettings.json` | single `DancingGoat` profile, no IIS settings, `launchBrowser: false`, repository's port |
| `AGENTS.md` | MCP servers described as configured in the repository root `.mcp.json`; `npm rebuild chromedriver` row in Useful commands |
| `.npmrc` | repository-only: `ignore-scripts=true` (chromedriver opt-in noted inside) |
| `README.md` | design skill and MCP servers described at the repository root |
| `packages.lock.json` | regenerated by restore; never merge by hand, take either side and restore with `--force-evaluate` |

Kept at the repository root instead of in `examples/DancingGoat` (the script strips them from both pristine projects):

- `Directory.Packages.props` → `examples/Directory.Packages.props` (Kentico versions; imports the root file for the rest)
- `.config/dotnet-tools.json` → root `.config/dotnet-tools.json`
- `.mcp.json` → root `.mcp.json` (repository's port and secret)
- `.github/skills/<name>` and `.claude/skills/<name>` → root `.claude/skills/<name>` (template content, a DancingGoat-scoped `description`, and a line saying paths are relative to `examples/DancingGoat/`)
